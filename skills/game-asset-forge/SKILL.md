# 游戏资产锻造

把“看起来不错”转换成可测量、可导入、可追溯的资产合同。生成器只是制作环节；最终产品是通过真实文件、引擎导入和运行截图验收的资产。

## 先读所需参考

- 制定尺寸、alpha、命名、目录和导入合同前，读 [references/asset-contracts.md](references/asset-contracts.md)。
- 制作角色、多帧动画、UI/图标或 Tileset 时，读 [references/specialized-assets.md](references/specialized-assets.md) 的对应章节。
- 进入 staging、像素/alpha 检查、引擎 import 和截图验收时，读 [references/qa-checklist.md](references/qa-checklist.md)。

## 建立资产合同

开始生成前明确：

- 目标引擎、渲染模式、用途与实际显示尺寸；
- 每项文件名、格式、像素尺寸、色彩空间、alpha、锚点/原点、边距和切片网格；
- 风格、视角、光向、比例、调色板、角色固定特征和参考图允许借鉴的维度；
- 数量、状态、帧序、fps、循环方式、tile 邻接与交付目录；
- 必须元素、禁止元素、精确文字和版权/IP 边界；
- smoke、选稿、仓库外 staging、引擎 import 与截图验收门禁。

项目已有命名、尺寸和 import 规则优先。信息缺失时采用最小可逆默认值并明确记录；会改变业务兼容性的歧义先请求确认。

## 固定参考并先 smoke

1. 选择一个项目/批次 ID，固定基准图、风格锚点和角色身份卡；后续变体从基准或最近邻编辑，不从零重抽。
2. 先生成一个最小代表样本，验证模型真实支持的参考输入、透明背景、尺寸、格式与输出限制。
3. 下载并读取真实文件；网页预览、模型自述和扩展名不算证据。
4. smoke 不合格时先修合同或生成路径，不批量放大缺陷。
5. smoke 通过且用户需要选稿时，先展示候选与推荐，再批量生成。

## 仓库外制作与单点返工

- 原图、候选、清理中间件、contact sheet 和淘汰稿放在唯一仓库外 staging 目录。
- 不把 `_raw_*`、`_staging*`、缓存、provider 响应或临时下载写入生产仓库。
- 每轮只修明确缺陷：身份漂移、轮廓、halo、伪文字、接缝、帧跳、尺寸或 alpha；避免无差别重抽。
- 凭证只从环境或受控凭证存储读取，不进入 prompt、命令回显、日志、文件名、元数据或提交。

## 按资产类型验收

- **角色/道具**：轮廓清晰，固定比例、面部、服装、配色、左右不对称和持物关系；多视图用观察者方向核对。
- **场景**：构图服务玩法安全区，透视、光向和尺度一致；可交互物与烘焙背景边界明确。
- **UI/图标**：集合级笔画、留白、填充和视觉重量一致；在真实小尺寸可读；非明确要求不含文字。
- **透明资产/特效**：检查直 alpha、半透明边缘、杂色像素和深浅背景 halo；不烘焙不需要的地面或投影。
- **动画**：帧名零填充、cell 一致、主体锚点稳定、相邻帧连续、最后到第一帧闭环；明确 fps。
- **Tileset**：真实拼成 2×2 检查接缝、重复地标、渐变和棋盘感；转角/边缘方向与引擎邻接规则一致。

## 最终交付

只有完成真实像素与 alpha 检查、精确命名、生产目录复制、引擎 import、实际场景加载和截图/运行验收后才声称“可直接导入”。交付时列出采用文件、实际尺寸/格式、生成与清理路径、合同偏差、QA 结果、引擎验证、未验证项和 Git 状态。
