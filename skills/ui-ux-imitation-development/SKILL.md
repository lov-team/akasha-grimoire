# UI/UX 模仿学习 Worker

职责链固定为：`找参考 → 同口径截图 → 半透明叠加分析 → 改进点清单 → 修改 → 复截图验证 → 提交`。本 worker 是 UI 代码的唯一写入者；作为两层结构的 worker 时，验收与 Git 收尾仍归监工（按 `agent-task-supervisor` 合同），独立使用时按下述流程自闭环。

## 1. 找到参考界面

按可靠性从高到低取参考图，取到一种即可：

1. 用户直接给的截图、设计稿或 URL。
2. 用户点名的产品/站点：用浏览器工具或 Playwright 打开并截图；需要登录或付费墙的页面截不到时，退回向用户要截图，不猜测样式。
3. 只有风格描述（"像 Linear 那样"）时，先向用户确认具体参考页面再截图；不凭印象生成参考。

参考图必须记录来源（URL 或用户提供）与截取时间。只学习布局、间距、层级、配色、字重、组件形态等**风格要素**；不复制受版权保护的图标、插画、字体文件和文案，不抄袭整页到像素级克隆商业产品。

## 2. 同口径截图现有界面

1. 用 `run` 技能或项目自己的启动方式跑起现有应用。
2. 与参考图使用相同视口宽度截图（参考图是移动端就用移动视口）；同一页面状态、同一滚动位置。
3. 多个目标页面各自独立成对截图，不混页比较。

## 3. 半透明叠加分析

对每对截图运行：

```bash
python3 scripts/overlay-compare.py current.png reference.png ./ui-analysis/<page>/
```

脚本输出 0.3/0.5/0.7 三档半透明叠加图、差异热区图 `diff_heat.png`、网格差异报告 `diff_grid.txt` 和 `summary.json`。分析时：

1. 先读叠加图，逐区域对照热区，把像素差异翻译成**设计语言差异**：布局结构（栅格、分栏、对齐）、间距节奏（padding/margin/留白密度）、层级（标题字阶、卡片阴影、分割方式）、配色（主色、中性色、对比度）、组件形态（圆角、边框、按钮/输入框样式）、字体（字号、字重、行高）。
2. 区分"应当学习的风格差异"与"内容不同导致的噪声差异"（文案长短、数据不同、图片不同），后者不进清单。
3. 交互行为差异（hover、过渡、反馈）叠加图看不出来，需实际操作两边界面对照记录。

## 4. 产出改进点清单

写成结构化清单文件（放 `ui-analysis/improvements.md`），每条包含：

| 字段 | 内容 |
| --- | --- |
| id | UI-1、UI-2… |
| 区域 | 页面 + 组件/热区坐标 |
| 现状 → 目标 | 现有表现与参考表现，用设计语言描述并给具体值（如 `16px → 24px`、`#333 → #1a1a1a`） |
| 类别 | 布局/间距/层级/配色/组件/字体/交互 |
| 影响文件 | 预计修改的样式/组件文件 |
| 优先级 | 高（结构性）/ 中（观感）/ 低（细节） |

清单完成后先交确认再动手：两层结构下发给监工/用户确认范围；独立使用时向用户呈现清单与叠加图，确认采纳哪些条目。**未经确认不得开始大范围改版**；用户已在任务中明确"直接改"的小范围调整除外。

## 5. 按清单修改

1. 在独立分支/worktree 内修改，只动清单中确认条目的影响文件；一次提交对应一批相关条目。
2. 优先改设计令牌/主题变量（色板、间距、字阶），让改动系统性生效；避免逐处硬编码。
3. 遵循项目现有样式体系（Tailwind/CSS 变量/组件库），不引入新 UI 依赖，除非清单条目明确需要且已确认。
4. 不改业务逻辑、数据流和接口；发现风格改动必须触碰逻辑时停下来按 `agent:blocked`/阻塞流程上报。

## 6. 复截图验证与提交

1. 用与第 2 步完全相同的口径复截图，重跑 overlay-compare，对照前后 `summary.json`：确认清单条目对应的热区差异收敛，且未引入新的高差异区域（回归）。
2. 逐条更新清单状态：done / 部分（写明剩余差距与原因）/ 放弃（写明理由）。
3. 跑项目既有 lint、类型检查和前端测试；截图证据（前后叠加图路径）写入交付。
4. 提交：作为两层监工结构 worker 时，按状态文件合同写 `DELIVERY_COMPLETE`，交付含改进点清单、前后 summary.json 对比和累计 diff，由监工验收后完成 Git 收尾；在 GitHub Issue 流水线中则自己 commit、push、开 PR（PR 描述附前后叠加图与清单），Issue 打 `agent:pr-open`；独立使用时按用户授权 commit。

## 边界

- 只做视觉与交互层的模仿改进；信息架构重组、新功能、文案重写都是范围外，出现时上报而不是顺手做。
- 参考界面的品牌标识、logo、专有图标不复制。
- 对比脚本只做同视口朴素对齐，截图口径不一致会产生大量噪声——口径错了先重截，不要在噪声上分析。
