# 核验、续跑与恢复

## 状态机

`planned → checking → uploading → submitted → reviewing → published`

异常分支为 `unknown` 或 `failed`。`unknown` 表示远端事实未查清，不等于失败；核验后再转为 `submitted`、`reviewing`、`published` 或 `failed`。

## CLI 卡住

1. 保存最后 100 行日志、进程 PID、开始时间、当前浏览器 URL 和页面标题。
2. 达到平台 Skill 的卡住阈值后终止该上传进程，不连带终止其他已确认任务。
3. 打开作品管理页，以精确标题、时长和提交时间查找条目。
4. 找到条目：记录远端状态和证据，继续下一平台。
5. 未找到条目：检查草稿、未通过与处理中列表；仍无条目时才决定重试。

## 账号校验超时

抖音等平台的创作后台偶尔超过 35 秒才返回。第一次超时后使用 90 秒单平台复检；只有明确输出 `invalid` 才进入重新登录。

## 中断续跑

运行 `status` 读取台账：

- `published`、`reviewing`、`submitted`：先核验，不自动重投；
- `unknown`：先核验作品管理页；
- `failed`：确认失败发生在点击发布前，且远端没有条目，再重试；
- 无记录：允许从账号校验开始。

## 视频号封面恢复

- 视频已上传但封面入口尚未出现：保留发布页，不点击发表；等待一次页面能力就绪并重新检查入口，仍缺失则记录 `unknown`、URL、日志与截图，只暂停视频号。
- 自定义封面上传、裁切、确认或预览核验失败：停在发表前，记录失败阶段；不得用平台自动封面冒充配置封面成功。
- 已发表或审核中才发现采用平台自动封面：先在作品管理页按精确标题确认远端条目；若封面已锁定，记录实际封面和锁定证据，不重复投稿。
- 后续恢复前再次查询精确标题；远端已有条目时只更新台账，不重新提交视频。

## 发布后证据

每个平台至少保存：精确标题、状态、提交时间、远端 ID/URL（如有）、管理页或 API 的字面结果、自定义封面是否真正采用。视频号封面证据还要明确记录“指定封面已上传并核验”“平台自动封面”“入口不可用”或“发表后锁定”之一。证据不能包含 Cookie、Token、请求签名或二维码内容。
