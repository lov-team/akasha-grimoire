# 视觉生产与验收

## 先选路线

- 观点、科普、教程和商业分析等文字型帖子默认使用 HTML/CSS 确定性排版，确保标题、正文、页码、线条和列表可控。
- 只有冻结合同明确需要照片、插画、人物、场景或其他生成视觉时才调用图片模型；不让图片模型承担长中文排版。
- 用户提供参考图时，先读取真实尺寸、页数、文字层级、留白、颜色和重复结构，不凭平台印象猜比例。

## 新视觉路线

1. 调研 3—5 个同平台、同主题、同内容形式的真实帖子，记录链接和实测尺寸。
2. 只提炼版式骨架，不复制文字、品牌标识、截图或未获许可素材。
3. 展示候选及推荐，等待用户选择。
4. 重点渲染封面，检查标题层级、断行、边距和手机缩略图。
5. 再渲染一张文字最密集的正文样卡，检查字号、行距、信息密度和裁切。
6. 封面与正文样卡确认后，按同一模板和内容地图批量生成其余页面。

视觉复杂度默认做减法。参考模板没有的进度条、多层卡片框、复杂关系图和装饰插画不自行增加。

## Akasha 图片调用

**REQUIRED SUB-SKILL:** 需要生成或编辑视觉素材时使用 `$gpt-image-generation`，先做一张最小 smoke，再扩大数量。缺少 Key 时使用 `$akasha-key-setup`；不把凭证写入 prompt、命令、日志或内容包。

生成素材先落到仓库外暂存区，读取真实格式、尺寸和内容后，再将采用版本放入内容包。API 成功只证明协议成功，逐图查看后才能进入正式卡片。

## HTML/CSS 导出合同

每张卡片是一个独立 HTML 文件；根页面锁定目标像素宽高、`margin: 0`、`overflow: hidden` 和本地可用字体。图片使用内容包内相对路径，不写本机绝对路径，也不依赖远程字体或运行时网络资源。将渲染器、viewport、字体、模板版本和输出写入 `generation-log.md`。

使用随 Skill 提供的零第三方依赖脚本调用本机 Chromium，并在落盘后核对 PNG 真实尺寸：

```bash
python3 "$content_pipeline_dir/scripts/render_html_card.py" \
  ./cards/html/xhs-01-cover.html \
  ./cards/output/xhs-01-cover.png \
  --size 1080x1440
```

`content_pipeline_dir` 是当前 `SKILL.md` 所在目录。脚本拒绝静默覆盖；明确返工时才加 `--overwrite`。自动发现失败时用 `--browser /absolute/path` 指定 Chromium、Chrome 或 Edge。渲染器或字体缺失时标记 `blocked`，不改用图片模型生成长中文排版。

所有最终卡片完成后，用同一浏览器生成确定性预览：网格预览最多三列、每张 `270 × 360`；手机预览为 `360 × 480` 的纵向序列。脚本同时保存对应 HTML：

```bash
python3 "$content_pipeline_dir/scripts/build_card_previews.py" \
  ./cards/output \
  --card-size 1080x1440
```

该命令只读取 `xhs-NN-*.png`，核对每张真实尺寸，并输出 `preview-grid.png`、`preview-mobile.png` 及 `cards/html/preview-*.html`。返工时显式添加 `--overwrite`。

## 卡片验收

- 默认 `1080 × 1440` PNG；用户或实测参考明确指定其他比例时按冻结合同执行。
- 每页只有一个核心意思，但正文必须包含足够的事实、论据、步骤或例子。
- 正文无错字、乱码、遮挡、溢出和错误裁切；装饰元素不得压住正文。
- HTML/CSS 成图逐字对照锁定文案；若使用模型生成含字素材，执行 OCR 后再人工核对。
- 同帖的字体层级、边距、颜色、页码和重复结构一致。
- 使用本地或系统字体、图片和无网络 HTML；实际预览若出现字体回退或素材缺失，标记 `blocked` 并修复后重渲染。
- 同时生成并查看全套网格预览和手机尺寸预览；原图也需逐张检查。
- 最终卡片数量、顺序和职责与 `brief.md`、`content-map.md`、`cards/plan.md` 一致。

不要用接口返回成功、HTML 文件存在或自动尺寸检查替代实际视觉验收。
