# 图文版式骨架库

这里记录可复用的版式骨架，不保存外部帖子截图、文字、品牌标识或其他受保护素材。每次使用仍需打开来源，重新核对当前页面、真实尺寸和适配性。

## 状态

- `historical`：曾在源项目完成成品，只能作为版式线索；不代表当前来源仍可访问或适合新内容。
- `candidate`：只完成初步调研；必须先展示给用户选择，不直接批量生产。

除非当前项目已经保存用户批准的视觉系统，否则每篇新内容都补充 3—5 个当前可访问的真实样本。下面的历史骨架不替代本轮调研。

## 历史骨架

### `editorial-numbered-single-column`

- 状态：`historical`
- 适用：观点长文、商业分析。
- 来源：源项目已完成帖子中的编辑部单列卡片；原外部帖子链接已失效，当前使用需重新找来源。
- 骨架：米白背景、浅色大页码、单列粗体标题、统一正文、蓝色细线、底部结论。
- 要点：先保留完整论证，再按核心观点拆页；HTML/CSS 排版。
- 避免：进度条、多层卡片框、复杂关系图和填空式装饰。

### `notebook-tool-intro`

- 状态：`historical`
- 适用：工具科普、开源项目介绍。
- 来源：源项目已完成 MediaCrawler 帖；原外部帖子链接已失效，当前使用需重新找来源。
- 骨架：暖黄外框、横线纸、左侧装订孔、粗黑字、少量荧光强调和步骤区。
- 要点：封面先说用户收益；正文分别讲能力、使用路径和结果。
- 避免：让 GitHub 标识、Star 数或装饰图形压过工具本身。

### `showcase-image-with-caption`

- 状态：`historical`
- 适用：AI 生图展示和提示词教学。
- 来源：原内容流水线中的已确认交付模式，无外部视觉素材。
- 骨架：图片只展示一张最终成品；平台标题独立；完整提示词和教学位于配文。
- 要点：先生成内部候选，确认后只保留一个最终方向。
- 避免：把完整提示词、教程、标签或 CTA 自动叠到成品图。

## 候选方向

- `minimal-editorial`：大留白、粗黑标题，适合信息较少且 Hook 足够强的内容。
- `dark-large-type`：深色大字封面，适合工具发布；正文页不要连续使用超大字。
- `handdrawn-process`：纵向步骤与少量批注，适合短流程，不适合密集公式和数据。
- `data-report`：页码、指标、表格和来源页脚，适合数据分析；必须放大移动端字号。
- `evidence-collage`：真实截图拼贴，适合产品实测；禁止虚构后台或暴露未脱敏数据。

候选方向只用于启动调研，仍需补齐 3—5 个当前真实来源并由用户确认。
