# 来源、原文忠实度与文案

## 研究合同

- 保存来源 URL、标题、作者或机构、访问时间和与本帖相关的摘录。
- 明确区分事实、直接引用、作者观点和 Agent 推断；当前产品、政策、价格和新闻需重新核实。
- 图片、截图和外部模板记录来源及使用边界；授权不清的素材只作研究参考。
- 没有证据时缩小表述，不用生成模型补齐数据、案例、体验或结果。

## 内容地图

先提取“核心判断—论据—例子—结论”，再决定卡片数量。每个核心点标记为：

- `保留`：含义和判断强度不变；
- `轻度改写`：只修病句、重复、断句或补充必要解释；
- `合并`：与相邻内容合并但保留依据；
- `删除`：说明理由；删除核心观点前取得用户确认。

用户提供个人观察或经历时，保留第一人称和实践感。假设、类比和方法示意必须标明性质，不把“例如”包装成已发生的客户案例。

## 文案门禁

- 一篇帖子保留一个主要结论；标题、封面与正文承诺一致。
- 标题默认不超过 20 个中文字符；确需更长时在 QA 记录理由。
- 开头独立建立话题和阅读理由，不堆抽象名词或故作悬念。
- 缩写首次出现时就地解释；中文去 AI 味只清理空话、套话、机械排比和不自然措辞，不把鲜明观点磨平成中性报告。
- 标签不堆无关热词；CTA 只在内容目标和语气自然匹配时加入。
- 图片与配文职责分开：卡片承担的核心论证必须进入卡片正文；已冻结为“纯成品图＋独立配文”的展示帖除外。

完成文案后逐项对照 `content-map.md`，确认每个保留或合并的核心点都有明确去向。
