# 抽象概念与经典文本动画解说

用于古典文本、哲学观点、组织关系、管理原则、心理机制等内容。目标是让观众看懂关系与因果，不是给原文逐句配图。

## 核心原则

1. **先找内容结构，再选择叙事形式。** 如果原文本身已经按角色、层次、位置或正反关系组织，默认直讲，不强套完整故事。
2. **翻译判断，不翻译名词。** 画面应呈现选择、约束、代价和结果；原文出现的器物、动物或动作不自动成为画面道具。
3. **一个镜头只表达一种关系。** 不要求一个镜头同时交代人物背景、冲突、转折和结论。
4. **可爱不等于低龄，易懂不等于浅。** 用自然人物比例、克制表演和清楚空间关系降低理解成本，不用知识卡、头像贴纸或儿童图标替代思想。
5. **旁白与画面分工。** 旁白解释判断；画面展示判断在空间和行动中如何成立，并尽量提供旁白没有直接说出的信息。
6. **动画必须有主体运动。** 头发、衣摆和镜头漂移只能作为辅助；人物选择、行走、交付、靠近、离开或队形变化才是叙事运动。
7. **风格一致性按镜头验收。** 末段或单个镜头成为极简平面、商务插画或不同年龄比例时，直接重生离群镜头，不靠调色掩盖。

## 内容阶段门

### 1. 提炼关系结构

先写一句核心判断，再将内容分成 2—4 组。每组回答：

- 谁处在什么位置；
- 谁拥有选择；
- 谁承担代价；
- 正向选择与反向选择分别导致什么结果；
- 本组与前后组的递进或辩证关系是什么。

原文引用、章节名和爻辞等材料单独列为屏幕文字，不要求旁白逐条朗读。

### 2. 写连续旁白

- 先讲问题，再自然进入各组关系；少用“第一条、第二条、某某爻说”等机械报幕。
- 用过渡句连接角色或层次变化，让观众听到的是一段完整解释，而不是六张知识卡。
- 控制每句只推进一个判断；长句按中文语义和标点断开，不能把“证明”等词拆成两条字幕。
- 先生成目标声线的 8—15 秒 smoke。以真实时长和试听感受决定总字数；舒缓语气通常需要更多停顿，而不是简单拉慢成片。

### 3. 建立视觉语法

为全片选择 2—3 个可复用的关系维度，例如：

- 距离：靠近、疏远、边界；
- 方向：同向、偏离、汇合；
- 中心：形成、开放、空缺；
- 节奏：主动、被推动、停下判断。

这些维度是镜头语言，不是必须贯穿全片的故事设定。每个核心镜头记录：空间位置、可见动作、选择权、代价、结果、画面新增信息和禁止出现的直译道具。

## 生成阶段门

### 4. 先做原生动态 smoke

选择最能代表全片难度的一个镜头，生成 4—5 秒原生 MP4。至少抽取开头、中段和结尾三帧，并检查：

- 主体是否持续运动，而非接近静帧；
- 动作是否清楚完成一个节拍；
- 人物比例、线稿、色彩和光线是否可作为全片锚点；
- 背景人数和物件是否克制；
- 是否出现文字、水印、畸形肢体或风格漂移。

smoke 未通过时只改单一变量后重试。smoke 通过后再批量生成，避免为错误路线同时生成六个镜头。

### 5. 批量生成

- 每条提示词只写一个主要动作和最多三个连续动作节拍。
- 写清起点、动作、终点、镜头运动和禁止项；不要用大量抽象形容词代替可见动作。
- 单主体或少量人物优先；复杂群体使用清楚队形和俯视构图。
- 同一组镜头复用色彩、人物年龄、服装和环境锚点。
- 每条结果立即探测时长、分辨率和音轨，并抽三帧审阅。离群镜头单独重生，不拖到全片合成后修补。

## 声音与文字

### 6. 旁白、原文和字幕分层

- 旁白专注解释内容；原文、章节名或爻辞使用章节卡。
- 章节卡在手机缩略图上仍须可读，可显示约 4—7 秒；长原文分行，不缩成装饰性小字。
- 普通字幕按中文标点组合短句，单屏优先 16—20 字，不从词语中间硬切。
- 最终混音重新转写，核对主要内容、专名和古文同音字；STT 同音误写不直接证明 TTS 读错。

### 7. 配乐可听而不抢话

- 生成无歌词、无突发高潮的候选，先听实际需要的完整区间。
- 旁白约 -16 LUFS；配乐可从 -24～-21.5 LUFS 试起。用户说“没有配乐”时，先检查可听度和 ducking，不要只确认音轨存在。
- 侧链只做轻度避让，避免把音乐持续压成近似静音；分别试听说话段和停顿段。
- 音乐长度不足时优先使用可自然循环的结构或更长候选，检查循环接缝。

## 剪辑与验收

### 8. 按真实声音铺画面

旁白完成后才锁定镜头时长。某段画面不足时依次选择：补覆盖镜头、缩短旁白、生成更长镜头、轻微变速。避免把 12 秒片段拉成 25 秒导致“明明是视频却像静态图”。

### 9. 同时检查技术与创作

除通用 `$video-qc` 外，至少检查：

- 全片是否存在持续两秒以上的静止区间；
- 每个核心镜头的开头、中段和结尾是否真的变化；
- 第一段是否建立运动和观看理由；
- 最后一段是否与前文风格一致；
- 每个章节卡是否明显、完整且在安全区；
- 字幕是否按语义断句；
- 配乐在说话段可辨、停顿段可听；
- 最终 MP4 是否位于用户可访问的项目或下载目录，而不只存在于缓存。

## 常见失败与修正

| 失败 | 根因 | 修正 |
|---|---|---|
| 原文提到器物，画面就出现同一器物 | 把解释误作逐字配图 | 先写器物承载的关系判断，再设计选择—代价—结果 |
| 为了“有故事感”强套统一事件 | 形式先于内容 | 保留原有分组，用直讲旁白和关系镜头 |
| 画面只有圆环、节点、卡片和箭头 | 抽象概念再次被抽象化 | 让人物位置、方向和动作承担第一次解释 |
| 静态图片加推拉被当成动画 | 交付类型判断错误 | 标为 animatic，或改用原生视频生成/动态图形 |
| 一张图上下塞两个场景 | 为省生成次数牺牲可读性 | 每个判断单独一个清楚镜头 |
| 未确认分镜就批量生图/视频 | 缺少阶段门 | 内容、分镜、动态 smoke 逐级通过后再扩量 |
| 提示词人物、道具和动作过多 | 单镜头负载过高 | 单主体、单焦点、最多三个连续动作节拍 |
| 旁白逐条报章节名和原文 | 声音结构机械割裂 | 原文放章节卡，旁白只讲连续解释 |
| 字幕从词中间断开 | 按字符数硬切 | 按中文标点和语义短语组合 |
| 最后一镜突然换成另一种画风 | 批量结果未逐镜审查 | 抽三帧比较锚点，单独重生离群镜头 |
| 配乐轨存在但观众听不见 | 归一化或侧链过度 | 检查分轨响度，减轻 ducking，试听停顿段 |
| 横版封面交成竖版，或只留背景图 | 发布资产未验证 | 输出后检查真实像素、文字排版和最终路径 |

## 发布包

用户需要发布时，再从已确认成片派生：

- 与平台一致的横版或竖版封面；
- 一个推荐标题和 2—3 个备用标题；
- 简介、一句话摘要、标签和置顶评论；
- 无文字背景、最终 PNG/JPEG 和真实像素记录。

先生成无文字背景，再用确定性排版叠加中文，避免模型生成错字。最终封面必须实际打开审阅，并复制到明确的交付目录。
