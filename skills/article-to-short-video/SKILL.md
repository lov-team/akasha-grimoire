# 文章转竖屏观点短视频

把“脚本、素材、声音、时间线、验收”作为一个闭环。先锁定主判断和证据边界，再消耗生成额度。

## 建立制作合同

1. 读取原文、同目录写作规范和人物资料底稿。
2. 明确时长、平台、画幅、语气、交付形态和不能使用的素材。
3. 将生成素材放在仓库外暂存区；只把脚本、SRT、分镜、渲染脚本和必要记录放进专题目录。
4. 建立素材清单，区分本人自述、官方资料、公开报道、网友二创、作者分析和 AI 意象。

默认合同：90 秒、1080×1920、30fps、H.264/AAC、26 条以内字幕、可重复 FFmpeg 工程与 MP4。需要具体目录结构、时间线配方和混音参数时，读取 [references/production-contract.md](references/production-contract.md)。

## 压缩脚本与分镜

**REQUIRED SUB-SKILL:** 使用 `$video-director` 将文章判断转换为 `brief.md`、`script.md`、`continuity.yaml` 和带稳定 `shot_id` 的 `shot-list.csv`；本 Skill 以下约束作为观点短视频场景的附加要求。

输入是古典文本、哲学观点、组织关系或其他抽象概念时，先读取 [references/abstract-concept-explainer.md](references/abstract-concept-explainer.md)。此类内容默认先解释关系和因果，不自动套完整故事，也不把原文名词逐字画成道具。

1. 用一句可争辩的判断统领全片，不按原文章节机械摘要。
2. 前 3 秒建立反差，20 秒内完成第一次观点推进，结尾回到文章独有判断。
3. 先用目标语气做短句 smoke，再按真实语速控制信息密度；舒缓知识旁白可从每秒约 4.2—5.0 个可见汉字起步，不用固定字数替代试听。为 TTS 展开易误读缩写，但字幕保留正确书写。
4. 以 3—8 秒为一个镜头单元，人物事实使用真实图片，抽象分析使用非肖像意象。
5. 不生成真实人物换脸、拟真替身或伪造文件；授权不明的视频只作研究参考。

进入批量生成前必须依次通过四个阶段门：内容分组和连续旁白、关系分镜、代表镜头动态 smoke、风格与运动验收。用户否决故事、意象或镜头路线时，只重做尚未确认的阶段，不把旧方案继续包装成成片。

需要外部图片、视频或 B-roll 时，**REQUIRED SUB-SKILL:** 使用 `$video-source-research` 按 `shot_id` 搜索、下载、探测并写入 `sources.json`。不要把浏览器搜索结果或下载器退出码直接当成采用素材。

## 先完成声音

1. 调用 `$fish-audio-speech` 检索公开参考音色，记录名称和 `reference_id`。
2. 先合成含人名、奖项和术语的 8—15 秒 smoke，并用 Fish STT 回验。
3. smoke 通过后合成全文；按实际语音逐句生成时间码，不沿用旧声线字幕。
4. 调用 `$suno-music-generation` 生成两首无歌词候选，默认使用当前 Skill 验证的最新模型。
5. 试听每首前 90 秒，选择不抢人声、没有突发高潮的版本。

真实调用会消耗额度。除非用户已经批准批量生成，否则先做一条语音 smoke 和一首/一组音乐候选。

## 组装与混音

**REQUIRED SUB-SKILL:** 使用 `$video-editing` 输出 `edl.json` 和可重复执行的渲染记录；以下参数作为本场景的剪辑默认值。

1. 旁白定时后再铺画面，避免按预估语速剪辑。
2. 字幕每屏不超过两行，位于竖屏安全区；姓名、数字和核心句必须人工核对。
3. 旁白目标约 -16 LUFS；配乐可从 -25～-22 LUFS 起步。
4. 用旁白作为 sidechain 控制信号压低音乐；必须分别试听说话段和停顿段，不能只确认音轨存在。
5. 片尾保留 2—4 秒呼吸，标注文章来源、主要人物素材来源和 AI 意象声明。

用户要求“动画”或“动态视频”时，主体动作必须来自原生视频、拍摄或明确的动态图形；静态图加推拉只能标为 animatic/动态样片，不能当作动画成片。生成片段若需要放慢超过约 30% 才能覆盖旁白，优先补镜头、缩短旁白或重生更长片段。

优先使用用户指定的可编辑剪辑工具；不可用时用 FFmpeg 脚本化合成，并保留旁白、音乐、SRT、分镜 CSV 和渲染脚本。

## 验收与交付

先运行随本 Skill 提供的竖屏专项检查器：

```bash
python3 scripts/validate_short_video.py \
  ./staging/final.mp4 \
  --srt ./project/captions.srt \
  --report ./staging/validation.json
```

再 **REQUIRED SUB-SKILL:** 使用 `$video-qc` 完成通用完整解码、冻结/静音检测、代表帧、叙事连续性、完整播放和来源追溯审阅。专项检查与通用 QA 必须同时通过。

验收必须覆盖：

- 时长、分辨率、帧率、编码、音轨和实际帧数；
- 整体 LUFS、True Peak、旁白清晰度与停顿处音乐可听度；
- 持续黑帧、片尾安全区、字幕行数和字幕越界；
- 开头、中段、结尾代表帧，以及所有姓名、奖项和术语；
- 素材来源、AI 画面声明和未确认授权边界。

只有检查器通过且人工完整播放无异常，才能宣称成片完成。交付 MP4、SRT、独立旁白、独立配乐、分镜/时间码工程和验收记录；大体积媒体默认不提交 Git。

用户需要发布素材时，再交付与平台画幅一致的封面、推荐标题、简介、标签和置顶评论。封面必须验证真实像素，并放在项目或下载目录；不要只留下仓库外缓存背景或把横版封面称为竖版封面。
