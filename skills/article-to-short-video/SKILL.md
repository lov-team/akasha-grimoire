# 文章转 Remotion 竖屏视频

先锁内容，再锁画面和声音，最后实现。默认使用 Remotion 制作画面；FFmpeg 只负责混音、检测和必要兜底。五个确认门不得合并或默认通过，即使用户一开始要求“直接生成成片”也要从门 1 开始。

需要目录、时间线、分页、混音和字幕参数时，读取 [references/production-contract.md](references/production-contract.md)。抽象概念先读取 [references/abstract-concept-explainer.md](references/abstract-concept-explainer.md)。先用 `$video-director` 建立带稳定 `shot_id` 的制作资产；最终工程与渲染使用 `$remotion-video-production`，声音设计复用其内置 video-shotcraft 资产和 `references/video-shotcraft/sound-design.md`；交付前再用 `$video-qc` 完成通用检查。

## 门 1：确认旁白与时长

1. 读取原文、同目录写作规范和人物资料；区分本人自述、官方资料、公开报道、网友二创、作者分析和 AI 意象。
2. 写旁白前先问用户希望观众看完记住什么、产生什么反应；用户说不清时给出 2—3 个传播重点供选择。把确认结果写成“全片传播重点”，再为每页指定唯一传播任务。未确认传播重点前不写旁白或设计画面。
3. 根据传播重点确定一句核心判断，再按内容转折提炼 3—6 个小标题。一个小标题就是一个页面，页面旁白只能服务该标题和本页唯一传播任务；不按字数机械分页，也不跨页重复结论。
4. 按“全片传播重点、核心判断、预计时长、逐页小标题、每页唯一传播任务、页面结论、完整旁白”返回内容合同。旁白每句只表达一个完整意思；长句在此处改写成完整短句，为字幕留出边界。
5. 先决定保留的内容，再按目标语速估算总时长，不预设 60 秒或 90 秒。单页过载时按“精简旁白 → 拆成两个小标题并说明理由 → 延长总时长”的顺序处理，不缩小文字、加速配音或硬塞页面。
6. 等待用户调整并明确确认传播重点、旁白、标题、分页和预计时长。确认前不生成配音、配乐、画面或 Remotion 工程。

## 门 2：确认排版与逐页动效

1. 提供 2—3 种有实质差异的标题主导排版方向。每种说明标题如何成为主角、主视觉形式、信息递进方式、跨页转场逻辑和贯穿全片的视觉线索；不能只报风格名称。
2. 用户选定方向后，在生成图片、页面图或静态预览前提供 2—3 种背景方案，让用户明确选择全片背景。背景方案要说明颜色、材质、空间感及其如何服务传播重点；未确认背景不生成画面。
3. 逐页设计必须由该页完整旁白和唯一传播任务决定。先用一句话写出该页唯一视觉事件，再输出小标题、页面目的、主视觉、信息层级、必要元素、跨页跳转和音效意图；不能拿全片流程替代当前页内容，也不能先套版式再填文字。
4. 每页围绕“一个核心判断 + 必要证据”建立唯一视觉焦点，排除权重相同的卡片堆叠和旁白逐句陈列。若遮住辅助文字后看不出本页重点，或删掉任一卡片仍不影响理解，回到内容理解重新提炼，不继续装饰版式。
5. 画面只保留标题、关键词、数字和理解当前页所必需的短句；删除英文眉题、页码、分类标签、“下一页”提示及无旁白依据的说明小字，不通过缩小字号塞入正文。
6. 检查垂直空间利用率、视觉连续性、安全区、遮挡和重叠。空白必须承担聚焦、停顿或转场作用；无意义的大面积空白通过调整位置、尺度或当前旁白直接推导的信息表达解决，不用无关装饰填充。
7. 动效确认前先用前端同时完整展示全部页面的静态终态，所有必要卡片和元素都必须可见，让用户检查信息是否齐全、主次是否清楚和空间是否合理；Remotion 只把确认后的静态排版动态化，不能靠隐藏尚未出现的元素掩盖排版问题。
8. 静态排版确认后，逐页写明什么先出现、什么随后进入、信息如何推进、落定后停留多久、页面如何离开。每页只让一个主动画成为焦点；动画必须使用内容对象自身的位移、形变、筛选、汇聚或传递解释内容，排除“标题加简单淡入”和纯装饰运动。
9. 成片画面禁止出现进度条，包括播放进度、百分比完成条、横向或纵向阶段线及伪装成流程传递的进度 UI。需要表达先后、处理或传递时，直接移动、变形、筛选、汇聚或交接内容对象。
10. 等待用户调整并明确确认全部静态页面和完整文字动态分镜。确认前不制作声音合成样片。
11. 需要外部图片、视频或 B-roll 时，使用 `$video-source-research` 按 `shot_id` 建立 `sources.json`；不得把搜索结果或下载器退出码直接当作采用素材。

## 门 3：确认声音合成样片

1. 从完整分镜中选择最能代表全片的一页，制作 8—15 秒 Remotion 合成样片，必须同时包含配音、BGM、页面转场 SFX、标题或关键动作 SFX、临时字幕和基础动效。
2. 调用 `$fish-audio-speech`，先运行 `fish_audio.py library` 展示共享中文声线库的名称、适用场景、听感和试听文件；用户可以选库内声线，也可以要求搜索新的公开声线。选定后合成覆盖人名、数字和术语的语音 smoke，并用 Fish STT 回验。不得在本 Skill 复制维护声线名单。调用 `$suno-music-generation` 时只生成足够放入样片试听的无歌词候选。真实调用会消耗额度，样片确认前不批量生成。
3. 让用户按成片语境确认音色、语速、停顿、情绪、BGM 风格与响度、转场音色和多轨关系；单独试听音轨不能代替合成样片确认。确认后才生成全文配音与完整配乐，再提交全文旁白和完整配乐供用户试听；两者确认后才能进入门 4。
4. 固定三层总线：VOICE 约 `-16 LUFS`；BGM 从 `-25～-22 LUFS` 起步并由旁白 sidechain ducking；SFX 只绑定真实动作或转场。以旁白听感为 `100` 时，SFX 默认只占 `10—15`，Remotion 中从 `volume={0.1—0.15}` 起步；不得用特效声压低或盖住旁白，重要 SFX 也只短暂压低 BGM `2—4 dB`。
5. SFX 使用中央注册表，以 `page.from + offset` 钉帧。同一时刻保留一个主音效、最多一个辅助音效；主音效默认不超过 `0.15`，辅助音效还要更低。长尾跨页时避让下一页同频段音效，长样本显式限制时长，总线末端加 limiter。素材原始响度差异先用试听、换样本或预归一化处理，不把单条 Remotion `volume` 抬过 `0.15`；只有用户明确要求强化某个钉点时才单独调整并重新确认样片。

## 门 4：确认字幕与完整时间线

1. 全文配音确认后，以最终音频时间码为唯一基准生成页面起止帧、转场帧、字幕和 SFX。不得沿用预估语速或旧音色时间码。
2. 默认 `CAPTION_LEAD_MS = 150`，即字幕比对应语音提前 150ms；允许按项目统一校准，但要记录最终值。
3. 每条字幕必须是一句完整语义句，不从句中硬切；最多两行并位于竖屏安全区。若两行放不下，回到门 1 精简或改写旁白，再重合成受影响语句，不能用缩小字号或删改字幕意思解决。
4. 人名、数字、术语和核心句必须人工核对。字幕可以贴近句尾消失，但不得在声音结束前消失。
5. 将最终逐页时间线、字幕提前量和 SFX 表交给用户确认。任何页面顺序或时长变化都会使该页及后续时间线失效，必须重算字幕、转场和全部受影响的 SFX 帧号。

## 门 5：确认成片

1. 用 Remotion 渲染完整成片，并从同一时间线输出带 BGM 版和无 BGM 但保留旁白与 SFX 的版本；FFmpeg 用于侧链、响度/峰值处理、探测和必要兜底。
2. 运行检查器并完整播放成片：

```bash
python3 scripts/validate_short_video.py \
  ./staging/final-with-bgm.mp4 \
  --duration <FINAL_DURATION_SECONDS> \
  --srt ./project/captions.srt \
  --report ./staging/validation.json
```

3. 再用 `$video-qc` 完成完整解码、冻结/静音检测、代表帧、叙事连续性、完整播放和来源追溯审阅。交付两版 MP4、SRT、独立旁白、独立配乐、代表帧、Remotion 时间线工程和 QA 报告。请用户审核内容、排版、动画、转场、字幕提前量和 VOICE/BGM/SFX 平衡。
4. 用户要求修改时从最早受影响的确认门重新开始：旁白/标题/分页回门 1，排版/动效/转场回门 2，音色/BGM/SFX 回门 3，字幕/时长/钉帧回门 4；重新确认后才能再渲染。检查器通过且人工完整播放无异常后，才宣称成片完成。

## 素材与验收边界

- 人物事实优先使用本人或官方资料；网友二创不能写成本人事实，作者分析不能伪装成当事人自述。
- 人物事实使用真实图片，抽象分析可使用非肖像 AI 意象；不生成真实人物换脸、拟真替身或伪造文件。
- 验收覆盖分辨率、帧率、帧数、音轨、整体 LUFS、True Peak、持续黑帧、字幕行数与安全区、代表帧和来源声明。
- 生成媒体放在仓库外暂存区；仓库内只保留可重复的旁白、字幕、分镜、时间线、渲染代码和必要记录，大体积媒体默认不提交 Git。
- 用户需要发布素材时，再交付与平台画幅一致的封面、推荐标题、简介、标签和置顶评论，并验证封面真实像素。
